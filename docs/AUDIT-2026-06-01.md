# Rusty Penguin — correctness audit, 2026-06-01

Focused sweep after the daily-driving feature sprint, before the visual polish
pass. Scope: kernel syscall pointer/bounds safety, desktop heap-leak hot paths
(the desktop allocator is a bump allocator that **never frees** + `panic=abort`,
so any leak eventually OOMs and any panic kills the whole desktop), and app
panics / OOB on edge input.

## Findings

### F1 — ImageViewer leaked a String every frame  · severity: medium · FIXED
`ImageViewer::render` built the `screenshots/shot-N.ppm` filename with
`String::from(...)` on **every** render. `render` runs whenever *any* window
recomposites (e.g. the Clock or Media Player animating), so the viewer leaked the
never-freeing bump heap steadily while open next to an animated app — eventual
allocator exhaustion → abort.
**Fix:** build the filename into a stack `[u8; 40]` buffer (no heap). Commit below.

### F2 — WAD loader sliced lumps without bounds-checking offsets · low · FIXED
`WadDoom::load_wad` sliced `&wad[ofs..ofs+size]` for PLAYPAL and every map lump
using offsets read straight from the WAD directory, validated only for the
directory itself — a corrupt/truncated `doom1.wad` would panic → abort the
desktop. `doom1.wad` is a trusted bundled asset, so real-world risk is low.
**Fix:** validate `ofs + size <= wad.len()` once in `get_lump` (covers all map
lumps) and add the same guard to the PLAYPAL slice.

### F3 — kernel trusts the desktop's user pointers · low · ACCEPTED POSTURE
`sys_video_blit` (#32) writes the decoded frame into the caller-supplied
backbuffer pointer; `sys_read`/`sys_write`/`sys_fb_query`/`sys_initrd_read` etc.
read/write caller buffers without validating they lie in the user address range.
In practice the writes are bounded by the framebuffer geometry, and the **only**
ring-3 process is our own trusted desktop. This is the kernel's documented
single-trusted-userspace posture (it is not multi-tenant hardened). **No fix** —
noted so it's a conscious decision, not an oversight. Revisit if/when untrusted
ring-3 programs run natively (the Linux-ABI shim already routes out separately).

## Verified clean
- `kernel/src/syscall.rs`, `kernel/src/rpv.rs`: no `unwrap`/`expect`/`panic!`.
  The new video syscalls (#30/#31/#32) index `FRAME`/the backbuffer within bounds
  (`sy<h`, `sx<w`, `py<fh`, `px<fw`); `.rpv` decode bounds-checks every segment.
- Desktop main loop: no per-frame heap allocation (numbers via a stack `Strbuf`
  / `u64_into`; the only `Vec`/`String` allocations are one-time or event-driven).
- New/changed apps (Media, Screenshot, ImageViewer, Clock, editor, files): no
  per-render allocation after F1; all divisions guard against zero; all slice
  ranges are length-checked.
- Release build (`panic=abort`, no overflow checks): integer underflows in layout
  math wrap to large values that `draw_str`/`set_pixel` clip — cosmetic, not
  panics. The single `*buf.last().unwrap()` in app.rs is guarded by `is_empty()`.

## Net
2 real fixes (1 medium leak, 1 low panic-hardening), 1 conscious posture note,
rest clean. No correctness regressions found in the sprint's new code.
